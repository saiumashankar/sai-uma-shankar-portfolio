      QuickPay: digital payment platform

      Three Spring Boot microservices (auth, payment, notification) and a Eureka registry, each with its own database, plus Redis, Apache Kafka and a React/TypeScript front end behind Nginx. Deployed on Azure.

      1.10soutbox drain time for a 1,000-payment burst, down from 31.75s
      366events left in the backlog, down from 1,800
      182automated tests run in CI on every change
      • No duplicate charges. Redis-backed idempotency keys fingerprint each request and return the original payment on retry.
      • State and events never diverge. The transactional outbox pattern publishes events to Kafka reliably. I sped it up by pipelining Kafka sends, removing a row lock that blocked payment writes, and indexing the poll query.
      • Bad messages can’t block good ones. Notifications are processed at-least-once with manual offset acknowledgement, Redis deduplication and a dead-letter topic.
      • Safer service calls. Resilience4j circuit breakers, OpenFeign timeouts, an internal API token and JWT access/refresh tokens. Prometheus metrics, health probes and structured JSON logs.
      • Automated delivery. GitHub Actions runs the tests, builds Docker images in parallel, logs in to Azure with keyless OIDC and publishes immutable commit-SHA images to Azure Container Registry.
      • Production setup. Azure VM with Docker Compose, managed identity for registry pulls, automatic HTTPS through Caddy and Let’s Encrypt, memory-limited containers and no secrets in source control.
